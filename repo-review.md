# Repository review: pre-launch course of action

**Recommendation: do not seed the current 84-product file or open checkout to customers yet.** The running site is healthy, but its 14-product catalog and the newly edited input file are incompatible. Resolve the catalog cutover, published claims, payment configuration, and end-to-end checkout before launch. This is a read-only review of application behavior; no deployment, seed, build, checkout, order placement, or capture was performed for this review.

## Evidence and scope

- Source reviewed across `themes/elune/`, `extensions/elune-catalog/`, `extensions/elune-payments/`, catalog/verification scripts, Compose configuration, and root product/implementation docs. No design mockups or archived mockups were inspected.
- `docker compose config --quiet` succeeded. `docker compose ps --all` showed healthy app and database; app was bound to `127.0.0.1:3010` at inspection time. `node --test tests/` in `extensions/elune-payments/` passed **5/5** predicate tests. These checks do not prove a customer can pay.
- Read-only database queries showed **14 active of 23 total product rows** and **5 active of 7 total category rows**. `SELECT sku FROM product ORDER BY product_id LIMIT 8` returned dashed SKUs including `BPC157-10MG`, `TB500-5MG`, `TB500-10MG`, and `CJC1295-5MG`. Live `/all` displayed 14 products with dashed SKUs. The 84-record `scripts/catalog-data.json` is the **outlier**, not evidence that the theme should be re-keyed to compact SKUs.
- Live `/`, `/all`, `/new-releases`, `/faqs`, `/shipping`, and `/contact` returned 200. `/robots.txt`, `/sitemap.xml`, the configured favicon PNG, and `/assets/plates/hero-photo.jpg.json` returned 200. Common `/privacy`, `/terms`, `/returns`, and `/refunds` paths returned 404; that does **not** establish that no policies exist at other URLs or in admin-managed CMS.
- Findings below distinguish observed failures, source-proven incompatibilities, and checks that need an isolated browser or operator confirmation. No secrets or `.env` values were read.

## 1. Stop-ship: catalog cutover and published product truth

- [ ] **Repair the 84-record input before running the seeder.** `scripts/seed-catalog.mjs:33-38` requires a SKU ending in `-${size.toUpperCase()}`; **84/84** SKUs in `scripts/catalog-data.json` fail this invariant (e.g. `BPC10` at `scripts/catalog-data.json:602-608`, versus live `BPC157-10MG`). Validation runs before login or writes (`scripts/seed-catalog.mjs:898-905`), so the current file cannot seed. Preserve actual SKU identities intentionally and audit every changed price, size, category, and stock quantity. Do not replace full catalog with `scripts/catalog-data.example.json`: that file has only 11 example records, and pruning retires any live SKU not declared (`scripts/seed-catalog.mjs:477-513`). **Check:** schema/business validation passes, approved SKU and price diff is explicit, and a seed succeeds twice on an isolated copy.
- [ ] **Align expanded catalog with exact-SKU content.** `themes/elune/src/data/productSpecs.ts:44-160,167-170` and `themes/elune/src/data/productLiterature.ts:50-269,275-278` each cover the original 14 dashed SKUs; neither has a key matching the 84 compact SKUs. A missing spec silently removes the entire table (`themes/elune/src/pages/productView/ProductSpecs.tsx:20-23`); a missing narrative removes the entire “About this compound” section (`themes/elune/src/pages/productView/ProductDescription.tsx:43-46`). Decide which new products are ready to publish, source their claims and content, and omit unsupported individual fields rather than guessing. **Check:** every published product page has the approved minimum record and no false specification/citation.
- [ ] **Migrate homepage bindings during the same cutover.** `themes/elune/src/pages/homepage/Elune.tsx:39-46,130-133` selects hero `BPC157-5MG` and four featured dashed SKUs by exact match. If changed or missing, hero Plate 01 disappears (`themes/elune/src/pages/homepage/Elune.tsx:199-235`) and featured cards drop out (`themes/elune/src/pages/homepage/Elune.tsx:292-314`). **Check:** homepage hero and intended four featured products render after seeding, with working links and specification rows.
- [ ] **Prove complete 84-product browse path, or provide pagination.** `/all`, `/new-releases`, and homepage all request argument-free `products { items }` (`themes/elune/src/pages/allProducts/AllProducts.tsx:90-119`; `themes/elune/src/pages/newReleases/NewReleases.tsx:85-114`; `themes/elune/src/pages/homepage/Elune.tsx:383-424`). `/all` counts and sorts only returned items and has no pagination (`themes/elune/src/pages/allProducts/AllProducts.tsx:39-43,74-77`). Seeder records a 20-row GraphQL product cap on its own read path (`scripts/seed-catalog.mjs:163-174`); whether the storefront resolver shares that cap remains **unverified**. `/new-releases` also chooses its six newest from only returned items (`themes/elune/src/pages/newReleases/NewReleases.tsx:39-46`). **Check:** rendered `/all` count and unique cards equal actual active products, all category pages link to them, and the six newest are genuinely the intended six.
- [ ] **Correct live FAQ batch/lot promises and purity wording.** Initial FAQ asserts each product has a batch/lot identifier and later promises “batch identity” (`scripts/seed-catalog.mjs:742-752`). Live `/faqs` actually displays both claims, but catalog schema has no batch/lot field (`scripts/catalog-schema.json:20-35`) and product specification data has none (`themes/elune/src/data/productSpecs.ts:18-32`). Homepage says “≥99% purity or we reject the batch” (`themes/elune/src/pages/homepage/Elune.tsx:170-182`), while product page explicitly calls purity a specification, not a batch result (`themes/elune/src/pages/productView/ProductSpecs.tsx:71-73`). Remove/reword the unbacked process/traceability claims or add actual evidence and records. Seeder creates CMS pages only when absent; editing `FAQ_BLOCKS` alone cannot repair live `/faqs` (`scripts/seed-catalog.mjs:836-864`). **Check:** homepage, FAQ, and product page tell the same defensible story.
- [ ] **Substantiate or remove marketing and review provenance claims.** Ribbon asserts batch tracking, “Best in class factory direct pricing,” and “Unbeatable delivery rate. Zero issues”; its own comments acknowledge missing batch, comparative-price and delivery data (`themes/elune/src/pages/homepage/Elune.tsx:54-64,243-258`; `PRODUCT.md:53`). Three reviews, names, dates and photos are hardcoded, yet the rendered sentence states they came from completed orders unedited (`themes/elune/src/pages/homepage/Elune.tsx:66-97,345-366`; `PRODUCT.md:63`). Ask owner for independently verifiable source material or change copy. No in-repo provenance does **not** prove reviews are fabricated. **Check:** retain only claims backed by owner-approved records.
- [ ] **Approve or replace mockup-derived hero asset before presenting it as product photography.** Hero references `/assets/plates/hero-photo.jpg` (`themes/elune/src/pages/homepage/Elune.tsx:199-213`). Public sidecar `themes/elune/public/assets/plates/hero-photo.jpg.json` identifies placeholder/mockup provenance and disclosed internal source paths; it returned 200 live. **Check:** owner approves representational imagery or replaces it, and public provenance sidecar is removed from deployed assets if inappropriate.

## 2. Stop-ship: checkout, payment, and contact

- [ ] **Configure the actual target store's payment method and rails.** Catalog seeder does not write `codPaymentStatus`, display name, or wallet settings (`README.md:146`; `PRODUCT.md:31-35`). Missing/invalid wallets render “Not configured — contact us before sending” without a Copy control (`themes/elune/src/pages/checkout/CashOnDelivery.tsx:89-116`). Save actual BTC, ETH and **USDT ERC-20** addresses and enable COD. Predicates validate address *shape*, not checksum or ownership (`extensions/elune-payments/src/lib/walletAddress.js:16-27`). **Check:** admin save and GraphQL read-back agree; each intended rail displays a copyable, independently verified destination on guest checkout. Never publish a sample address.
- [ ] **Approve payment instructions and manual capture procedure.** When no instructions setting row exists, resolver says “We confirm on-chain and ship after 1 network confirmation” (`extensions/elune-payments/src/graphql/types/Setting/CryptoWalletSetting.resolvers.js:24-30`); there is no on-chain watcher and capture is manual (`PRODUCT.md:35,70-72`; `SPEC.md:41-47`). Align public instruction, actual network confirmation policy, support and dispatch process. **Check:** real isolated order goes from pending to paid via authorized capture; a second capture is rejected; order confirmation shows TXID. `themes/elune/src/pages/checkoutSuccess/ConfirmationStatus.tsx:39` conditionally hides the TXID when `showShippingNote` is off—verify the configured path.
- [ ] **Configure real shipping before running any mutating smoke.** On a store without shipping methods, `scripts/smoke-checkout.mjs:158-204` creates a persistent US “Smoke Zone,” enabled “Flat Rate” method and **$5** rate. The script also places and captures an order (`README.md:205-226`). Use staging or an isolated store, or explicitly approve and inspect production rates and cleanup. **Check:** configured zones/rates match actual destinations and economics; no smoke-created method or test order remains mistaken for live business data.
- [ ] **Set and publish a working contact address.** Live `/contact` says none is configured. Seeder reads `storeEmail` into a create-only CMS page (`scripts/seed-catalog.mjs:797-816,866-895`); setting email afterward does not refresh existing content. **Check:** update the existing CMS page through admin, then verify email and contact route on public site.
- [ ] **Confirm legal/consumer terms with owner/counsel.** Age gate says entrants accept “our terms of sale” but provides no terms link (`themes/elune/src/pages/all/AgeGate.tsx:85-95`). Root docs do not specify privacy, refunds/returns, tax/customs, or crypto-payment policy; the common policy paths checked returned 404. Confirm applicable requirements, publish approved pages and link them from purchasing surfaces. “Payments” deliberately points to `/faqs`, not a dedicated payment page (`PRODUCT.md:9`); decide if that page answers its label. This is a launch decision, **not** a finding that every jurisdiction requires a particular page.
- [ ] **Verify currency, price, stock and fulfilment against reality.** Copy says USD while seeder does not set currency (`PRODUCT.md:69`). New catalog records declare `qty: 100` throughout representative rows (`scripts/catalog-data.json:24-49,593-626`); FAQ/shipping copy says hand-confirmed payment, supplier fulfilment, tracked/discreet flat-rate shipping (`scripts/seed-catalog.mjs:754-789`). **Check:** admin currency, checkout/order totals, sellable quantities, inventory policy, supplier capability, rate table and lead times agree with public text.

## 3. Required release verification and deployment controls

- [ ] **Fix regression script against approved catalog and rendered card.** Smoke defaults to dashed `BPC157-10MG` and prices tied to original catalog (`scripts/smoke-checkout.mjs:59-67`); current 84-record file uses compact `BPC10` at a different price (`scripts/catalog-data.json:602-608`). Using an override SKU skips price/Size checks when not in `KNOWN_VARIANTS` (`scripts/smoke-checkout.mjs:641-654`). Browser monitor looks for `:scope > div .mono` (`scripts/smoke-checkout.mjs:392`), whereas current card puts SKU on `data-product-sku` and `.mono` contains form/size (`themes/elune/src/components/frontStore/catalog/ProductListItemRender.tsx:164-170,211-215`). Compare requested/clicked/posted SKU and retain meaningful price/Size assertions. **Check:** browser and REST smoke pass for approved SKU, no assertion silently skipped.
- [ ] **Run browser path without a silent SKIP.** Smoke browser assertion skips non-loopback storefronts while REST steps continue (`README.md:226`). On isolated environment, exercise single-size and multi-size selection, displayed and ordered price/SKU, add-to-cart busy state, guest checkout, wallet, TXID, confirmation and manual capture. Variant selector has a null option-item override and converts option ID with `Number` (`themes/elune/src/components/frontStore/catalog/DefaultVariantSelectorRender.tsx:7-33`); checkout calls hooks from `checkoutButtonRenderer`, whose core invocation timing has not been verified (`themes/elune/src/pages/checkout/CashOnDelivery.tsx:164-166`). **Check:** no browser `SKIP`, no invalid-hook error, each variant orders intended SKU and price.
- [ ] **Rehearse seed on isolated copy and require two clean runs.** Seeder validates then sets store settings, upserts products, reconciles Size groups inside a transaction, retires undeclared rows, asserts results, and creates CMS pages (`scripts/seed-catalog.mjs:898-920`). Entire seed is **not** one transaction; planned retirements and existing orders need review first. `dbProducts` falls back to a capped GraphQL scan when direct DB read fails; prune skips without DB reads (`scripts/seed-catalog.mjs:163-174,202-245,481-487`). Run in app container as documented (`README.md:150-158`); require no fallback warning, `SEED FAILURE`, undeclared retirement, duplicate or incomplete product. Root `npm run seed` is EverShop demo seed, not this catalog (`package.json:8-17`; `README.md:64`).
- [ ] **Build and verify actual production artifacts.** Compose uses `NODE_ENV=production`, extensions load compiled `dist`, and theme `dist` is gitignored (`docker-compose.yml:9`; `README.md:180-203`). Build theme, both extensions and EverShop bundle in documented order; confirm healthy app and changed routes after build. `scripts/restart.sh:1-3` does not recreate the container: `.env` or `HOME_URL` changes need app recreation. Avoid restarting while bundle writes are in progress.
- [ ] **Confirm external HTTPS/base URL and transactional messages.** Compose defaults to loopback; `HOME_URL` is injected as `EVERSHOP_HOME_URL` at container creation (`docker-compose.yml:13-25`; `README.md:82-97`). Rendered canonicals currently use an HTTPS Tailscale hostname, but external checkout reachability and email delivery were not exercised. Verify browser origin equals baked base URL, cart actions and email links use that origin, and sender/SMTP settings produce expected order notices. Recreate app after URL changes.
- [ ] **Replace illustrative credentials and rehearse recovery.** `.env.example:7` uses `change-me-strong`, which satisfies Compose's nonempty guard (`docker-compose.yml:50`); README illustrates admin password `ChangeMe123` (`README.md:50-55,154-157`). Actual secret values were not inspected. Set unique credentials before a new DB is initialized; changing DB env afterward does not rotate the PostgreSQL role (`README.md:44`). Compose retains DB, media, public/build and logs in separate named volumes (`docker-compose.yml:26-34,62-67`); database-only dump does not restore uploaded media. Test off-host DB **and media** backup and restore, retention and rollback; do not destroy named volumes before backup.
- [ ] **Verify session-secret and secret-file handling before adding configuration.** Repo `config/default.json:1-22` does not specify a session cookie secret; actual EverShop 2.2.1 default/generation behavior remains unverified. `.gitignore:8-12` ignores `.env` but not potential `.env.*` or `config/local.json`; none of those sensitive alternatives were found tracked in this review. Check image behavior and secure any new local secret file before creating it. Do not call current configuration a proven cookie vulnerability without checking the running image.
- [ ] **Define launch gate, monitoring and manual operations.** Compose healthchecks exist (`docker-compose.yml:35-59`) but root verification table covers only Compose, stack, wallet tests, seed, checkout and manual age/RUO (`SPEC.md:293-302`). Assign owner sign-off, order/payment reconciliation, stock and shipment monitoring, log retention, backup cadence, incident path and rollback trigger. Do not promote release before review checkpoint/owner approval.

## 4. Polish and hand-off, after stop-ship items

- [ ] **Check SEO from rendered pages, not only theme source.** Current pages emitted titles, meta descriptions and canonicals; `/robots.txt` and `/sitemap.xml` returned 200. Seeder sets store name, description and favicon only when missing (`scripts/seed-catalog.mjs:643-695`). Verify rendered `<link rel="icon">` and actual sitemap entries after catalog cutover, and verify each page's title/canonical/description. Missing theme-level head code alone is **not** an SEO failure because EverShop supplies head tags.
- [ ] **Handle empty categories and age-modal accessibility.** `themes/elune/src/components/frontStore/catalog/CategoryProducts.tsx:8-30` renders grid/count without an empty-state message. Age gate traps keyboard Tab, but only locks body scroll; no background `inert`/equivalent is set (`themes/elune/src/pages/all/AgeGate.tsx:23-71`). It is cookie-based presentation, not server-side age verification (`PRODUCT.md:43,73`). Verify with keyboard/screen reader, then decide whether legal context demands a stronger gate.
- [ ] **Reconcile documentation with final catalog.** `README.md:163-174` still calls catalog 14 products; `PRODUCT.md:17-27` documents prior 14 dashed SKUs. Several root links point at absent `*-grok-unapproved*` filenames (`README.md:7-12`; `ARCHITECTURE.md:41,67,102`; `DESIGN.md:221,250`). Update counts, examples, rerun instructions and links only after approved cutover. Avoid treating stale `scripts/cut-dag.sh` as launch contract (`README.md:270`).
- [ ] **Run a type/static and visual pass.** Theme's build uses SWC without typechecking (`themes/elune/package.json:6-8`). Test focused TypeScript diagnostics and desktop/mobile UI with real browser—especially cart busy state, variants, age gate, category grid and checkout. Wallet predicate tests passed, but admin setting persistence, checkout presentation and payment capture have not been demonstrated here.

## Release decision

Proceed only after: catalog data validates and safe two-run seed preserves intended stock; every published SKU has approved content; batch/testimonial claims are resolved; real wallets, shipping, contact and applicable policies are configured; browser checkout plus capture succeeds without skipped assertions; HTTPS origin, backups and owner sign-off are verified. Current healthy 14-product storefront is **not** proof that the incompatible 84-product source can be launched.
